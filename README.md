# FlowTrack — умный трекер бюджета с AI

Загружаешь выписку Kaspi / Halyk, и приложение само раскладывает траты по категориям, сравнивает месяцы, считает прогноз до конца месяца и следит за целью накопления.

## Что умеет

| Функция | Как работает |
|---|---|
| **Импорт выписок** | Kaspi Gold (PDF), Halyk и другие банки (PDF, CSV, Excel .xlsx). Повторная загрузка той же выписки не создаёт дублей |
| **Автокатегории** | Yandex Go → Транспорт, Glovo → Кафе и доставка, Magnum → Продукты и т.д. Порядок: твои правила → словарь мерчантов КЗ → AI (Claude) для незнакомых |
| **Обучение на правках** | Поменял категорию и отметил «запомнить» → дальше такой мерчант сразу попадает куда нужно, старые операции тоже обновляются |
| **Цель** | «1 000 000 ₸ к 27.01.2027»: сколько откладывать в месяц, успеваешь ли, сколько будет к сроку |
| **AI-помощник** | «В этом месяце ты потратил на 31% больше… к концу месяца останется… по цели ты в минусе на…» + лимит трат в день |
| **Аналитика** | Доходы/расходы по месяцам, категории с изменением к прошлому месяцу, топ мерчантов, динамика категорий |
| **Прогноз** | График накопленных трат: этот месяц, прошлый и прогноз до конца месяца |

Цифры всегда считает сервер (`server/lib/forecast.js`), AI только формулирует совет. Без ключа API всё работает на словаре и шаблонных подсказках.

## Структура

```
src/                     фронтенд (React)
  pages/Import.js        загрузка выписки, просмотр и правка категорий
  pages/Dashboard.js     главная: AI-помощник, цель, категории
  components/CoachCard   карточка AI-помощника
  components/GoalCard    цель накопления
server/                  бэкенд (Express + MySQL)
  app.js                 все API-маршруты
  db.js                  подключение и автоматическое обновление схемы БД
  lib/parsers.js         разбор Kaspi / Halyk / CSV / Excel
  lib/categories.js      категории и словарь мерчантов Казахстана
  lib/categorize.js      определение категории
  lib/forecast.js        прогноз и расчёт цели
  lib/ai.js              запросы к Claude API
  tests/                 тесты (npm test)
samples/kaspi-demo.pdf   демо-выписка со сгенерированными данными
```

## Запуск локально

1. MySQL: создай пустую базу `flowtrack`. Таблицы сервер создаст сам. Старая база тоже подойдёт: недостающие колонки добавятся, данные останутся.
2. Бэкенд:
   ```bash
   cd server
   cp .env.example .env      # заполни доступ к БД и JWT_SECRET
   npm install
   npm run dev               # http://localhost:5000
   ```
3. Фронтенд (в корне проекта):
   ```bash
   npm install
   npm start                 # http://localhost:3000
   ```
4. Зарегистрируйся и загрузи `samples/kaspi-demo.pdf` или свою выписку.

## Переменные окружения (server/.env или Railway → Variables)

| Переменная | Зачем |
|---|---|
| `MYSQLHOST`, `MYSQLPORT`, `MYSQLUSER`, `MYSQLPASSWORD`, `MYSQLDATABASE` | доступ к БД (на Railway создаются автоматически) |
| `JWT_SECRET` | **обязательно** длинная случайная строка, иначе после перезапуска всех разлогинит |
| `DATA_KEY` | **обязательно в продакшене**: ключ шифрования (64 hex). Потеряешь — данные не расшифровать |
| `ANTHROPIC_API_KEY` | ключ Claude API с console.anthropic.com. Необязательно |
| `AI_MODEL_FAST`, `AI_MODEL` | модели для категорий/советов и для разбора незнакомых PDF (по умолчанию `claude-haiku-5-5` и `claude-sonnet-5-5`) |
| `APP_TZ` | часовой пояс, по умолчанию `Asia/Almaty` |
| `CORS_ORIGIN` | адрес фронтенда, например `https://flowtrack.vercel.app` |

Фронтенд берёт адрес API из `REACT_APP_API_URL` (`.env.production` / `.env.development`).

## Деплой на Railway

- Сервис бэкенда: Root Directory = `server`, Start Command = `npm start`.
- Добавь `JWT_SECRET` (и по желанию `ANTHROPIC_API_KEY`) в Variables.
- Схема БД обновится сама при первом запуске.

## Как выгрузить выписку из Kaspi

Kaspi.kz → Мой банк → Kaspi Gold → Выписка → выбери период → Отправить/Скачать PDF.

## Безопасность

| Угроза | Защита в проекте |
|---|---|
| SQL Injection | Только параметризованные запросы (`?`-плейсхолдеры mysql2), без склейки строк |
| XSS | React экранирует весь вывод, нет `innerHTML`; сервер чистит управляющие символы и проверяет категории по белому списку; заголовки Helmet (CSP, nosniff) |
| CSRF | Токен передаётся в заголовке `Authorization`, а не в cookie, поэтому чужой сайт не может отправить запрос от имени пользователя |
| Brute Force | 10 неудачных входов на IP+email и 50 на IP за 15 минут, затем 429; одинаковое время ответа для существующих и несуществующих email |
| JWT Theft | Срок жизни 1 день, алгоритм зафиксирован (HS256, `alg=none` отклоняется), HTTPS на Railway, HSTS |
| Broken Access Control | Каждый запрос проверяет `user_id` владельца; чужие записи отдают 404 |
| Insecure File Upload | Белый список расширений и MIME, проверка сигнатуры файла, лимит 15 МБ, файл хранится только в памяти и никогда не исполняется |
| Data Leakage | Пароли — bcrypt; секреты только в переменных окружения; `.env` в `.gitignore`; номера карт не хранятся |
| Session Hijacking | Серверных сессий и cookie нет; токен подписан и истекает |
| Спам | Общий лимит 600 запросов / 15 мин на IP, 60 записей в минуту на пользователя, 10 регистраций в час на IP |

Пароль: минимум 8 символов, буквы и цифры.

## Персональные данные

| Мера | Как сделано |
|---|---|
| Файл выписки | Читается в памяти и не сохраняется; в базу попадают только операции |
| Шифрование | Описания операций — AES-256-GCM (`DATA_KEY`), старые записи шифруются при запуске |
| AI | Только с отдельного согласия пользователя (трансграничная передача, ст. 16 и ст. 8 п. 4 Закона РК № 94-V). Перед отправкой вырезаются ФИО, ИИН, карты, IBAN, телефоны, email; имена получателей переводов в AI не уходят |
| Третьи лица | Полные ФИО получателей сокращаются до «Имя Ф.» |
| Согласие | Чекбокс при регистрации, в базе хранятся дата и версия политики; при новой версии политики пользователь подтверждает заново |
| Права пользователя | Выгрузка всех данных (JSON), полное удаление аккаунта, отзыв согласия на AI — в настройках |
| Политика | `/privacy` — **черновик**, заполнить реквизиты в [скобках] и согласовать с юристом |

### Перед запуском с реальными пользователями
- **Хостинг базы в РК.** С 25.08.2026 персональные данные граждан РК должны храниться в базе/цифровом объекте на территории Казахстана (ст. 12 п. 2). Railway (США/ЕС) для продакшена не подходит — нужен дата-центр в РК (например, Yandex Cloud регион kz1, PS Cloud, QazCloud).
- Утечки — уведомление уполномоченного органа в течение 1 рабочего дня.
- Запросы пользователей — ответ в течение 3 рабочих дней.
